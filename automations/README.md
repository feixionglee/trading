来源：用户上传的 `stock-market-migration.zip` 中的 `automations/`。这是上传时的快照，不保证与旧电脑当前配置一致。

| 目录 | 任务 |
| --- | --- |
| `a/` | A 股高科技与龙头盘前分析 |
| `v2/` | 美股盘前市场分析 |
| `v2-2/` | 美股收盘前市场分析 |

三份 `automation.toml` 按原内容保存，包括原状态、时间、旧电脑路径、账户选择信息和项目/线程关联。文件里的 `ACTIVE` 仅反映源配置，不代表任务已在 GitHub 或云环境启用。美股任务当前为固定 UTC 时间，冬令时会比常规开盘/收盘前一小时提前一小时。

## 在另一台电脑迁移

1. 安装 Codex 并克隆本仓库，备份新电脑已有的任务配置。
2. 将需要的任务目录复制到实际的 `$CODEX_HOME/automations/`；默认通常是 `~/.codex/automations/`。不要覆盖同 ID 的现有任务。
3. 在 Codex 的自动化界面检查识别结果。按新电脑更新工作目录、提示词中的输出路径，以及项目或线程关联；不能假设旧项目 ID 在新机器有效。界面不识别文件时，通过界面按配置重建任务。
4. 重新连接所需工具，手动验证输出，再验证一次定时触发。切换后停用旧电脑对应任务，避免重复执行。

本目录不包含 `memory.md`（可能含账户和持仓信息）以及 `.run-jitter-salt`（本地调度器状态）。它们仍保留在上传的原始 ZIP 中。这里的配置含个人路径和关联信息，公开仓库前需另行脱敏。

复制配置或推送 GitHub 不会启用云端调度。新电脑迁移仍需验证 Codex 的后台运行条件。
